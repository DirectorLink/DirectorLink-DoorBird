## DirectorLink · DoorBird 1.0.0-beta.1

**Beta.** First release. Make a DoorBird user for Control4, enter its login, and the DoorBird's rings, motion, RFID tags and relays are in Control4, with pictures and live video, and with DirectorLink.

Free, open-source Control4 driver for DoorBird video door stations. Part of [DirectorLink Drivers](https://directorlink.io/drivers). Free. No subscription, no license key, no account with us. Works on its own: DirectorLink is not required.

This beta follows DoorBird's published LAN API and the way Home Assistant's DoorBird integration uses it, and passes its tests against recorded API answers, but it has not run on a real DoorBird yet. It stays a beta until an installer's logs confirm rings, motion, pictures, video and the relays. If you try it, please send the log (see *Testing the beta* in the README).

### File

| Driver in Composer | File |
|---|---|
| DirectorLink · DoorBird | `DirectorLink-DoorBird.c4z` |

Check the download against `SHA256SUMS.txt`. Keep the file name exactly as it is: a browser's `(1).c4z` copy installs as a separate driver.

### What it does

- **Official LAN API only**, on the home network, with a DoorBird user made for Control4 (API-Operator, Watch Always, History, Motion). A missing permission is named; without API-Operator the driver refuses events and says so.
- **Events the way Home Assistant gets them**: its own HTTP calls on the DoorBird, one per event, with a random token, in the DoorBird's schedule for each button, motion, the RFID tags and each relay. Taken only from the DoorBird's address and with the token.
- **Leaves everything else alone**: the DoorBird app's notifications, other apps' HTTP calls (the official DoorBird driver's too), SIP and relays stay exactly as they were. Each entry is read just before it is written and checked right after; if the DoorBird keeps one HTTP call per event, the driver puts the other app's back and says so.
- **Cleans up after itself** with Remove From DoorBird (run it before deleting the driver) and when the address changes.
- **Camera**: pictures, H.264 live video (RTSP on 554 or 8557), MJPEG fallback, a notification picture at each ring and motion alert.
- **Relays**: one Control4 relay connection per DoorBird relay for Relay Door, Gate and Garage Controllers. A pulse only, never held.
- **Programming**: Ring, Doorbell Pressed per button, Motion Detected, Alert, RFID Read, Door Opened per relay, DoorBird Online/Offline; Open Door, IR light, alert on motion.
- **With DirectorLink 1.10**: rings with the live picture on the phone, motion alerts, opening the gate with two taps (the DirectorLink camera agreement).
- **Print Diagnostics**, Test Pictures and Debug logging, never with the password or the token.

### Installing

1. Upload the file with **Driver → Add or Update Driver or Agent**.
2. In the DoorBird app, make a user for Control4 with API-Operator, Watch Always, History and Motion.
3. Search **DirectorLink**, add **DirectorLink · DoorBird**, and enter the DoorBird's IP, the user and its password.

Requirements: Control4 OS 3.3.0 or newer, Composer Pro, DoorBird firmware 000110 or newer for events. Full steps: [directorlink.io/drivers/doorbird](https://directorlink.io/drivers/doorbird).

### Known issues

- **Not yet confirmed on a real DoorBird** (the reason for the beta).
- **Control4 Intercom and audio/SIP are not included.** Installers who use Control4 Intercom with the DoorBird keep the official DoorBird driver for that; both can run side by side.
- **One HTTP call per event:** if a DoorBird keeps only one HTTP call per event and another app already has it, that event stays with the other app (Attention says which).
- **Relays of a paired I/O Door Controller** can be opened, but the DoorBird does not report when they open by themselves.
- **Away from home** (4Sight), pictures and live video are not expected to work: the camera page holds the home network's address.
