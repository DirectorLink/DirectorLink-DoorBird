## DirectorLink · DoorBird 1.0.0-beta.2

**Beta.** Redesigned after the first run on a real DoorBird: a **DoorBird tile** that shows what is happening at the door and opens the gate with a tap, a **DoorBird Camera**, eight properties instead of nineteen, and keypad codes.

Free, open-source Control4 driver for DoorBird video door stations. Part of [DirectorLink Drivers](https://directorlink.io/drivers). Free. No subscription, no license key, no account with us. Works on its own: DirectorLink is not required.

Beta.1 ran on a DoorBird D2101KV (firmware 000152): the login, pictures, registering the events next to other apps' HTTP calls, rings and motion are confirmed in the controller's log. It stays a beta until the gate (relays) and live video are confirmed too. If you try it, please send the log (see *Testing the beta* in the README).

### Coming from beta.1

Beta.2 adds different devices, so it cannot update a beta.1 in place:

1. On the beta.1 driver run **Remove From DoorBird**, then delete it from the project.
2. Upload this file (**Driver → Add or Update Driver or Agent**) and add **DirectorLink · DoorBird** to the room.
3. Enter the Address, Username and Password, bind your Relay Gate (or Door) Controller to **Relay 1**, and make the programming again (the event ids are new).

A beta.1 deleted without Remove From DoorBird leaves HTTP calls on the DoorBird; beta.2 finds them and removes them.

### What changed

- **Two devices:** **DoorBird**, the tile in the Control4 apps (its icon shows a ring, motion, the gate opening or the DoorBird offline; a tap opens the gate), and **DoorBird Camera** for pictures and live video.
- **Eight properties:** Status, DoorBird, Address, Username, Password, Gate Relay, Alert On Motion, Log Level. **Status** also says the first thing to fix; everything else is in **Print Diagnostics**.
- **Gate Relay** and the **Open Gate** action: the relay a tap on the tile opens (Relay 1 by default, or Nothing).
- **Keypad codes:** each code gets its own HTTP call; **Keypad Code Entered** fires and `LAST_KEYPAD_CODE` holds the code for programming. Codes are masked like the password: never in a log, Status, Print Diagnostics or the Control4 History. RFID tag numbers too.
- **Events:** Ring (and Ring (Button n) only on a DoorBird with several buttons), Keypad Code Entered, Motion Detected, Alert, RFID Read, Door Opened, DoorBird Online/Offline.
- **RTSP over HTTP:** set RTSP Port 8557 on the DoorBird Camera's Properties page; the driver keeps it.
- HTTP calls of an earlier copy at another port of this controller are removed only when nothing answers there.

### What it does

- **Official LAN API only**, on the home network, with a DoorBird user made for Control4 (API-Operator, Watch Always, History, Motion). A missing permission is named; without API-Operator the driver refuses events and says so.
- **Events the way Home Assistant gets them**: its own HTTP calls on the DoorBird, one per event, with a random token, in the DoorBird's schedule for each button, keypad code, motion, the RFID tags and each relay. Taken only from the DoorBird's address and with the token.
- **Leaves everything else alone**: the DoorBird app's notifications, a keypad code's own relay, other apps' HTTP calls (the official DoorBird driver's too), SIP and relays stay exactly as they were. Each entry is read just before it is written and checked right after.
- **Cleans up after itself** with Remove From DoorBird (run it before deleting the driver) and when the address changes.
- **Relays**: one Control4 relay connection per DoorBird relay for Relay Door, Gate and Garage Controllers. A pulse only, never held.
- **With DirectorLink 1.10**: rings with the live picture on the phone, motion alerts, opening the gate with two taps (the DirectorLink camera agreement).

Requirements: Control4 OS 3.3.0 or newer, Composer Pro, DoorBird firmware 000110 or newer for events. Full steps: [directorlink.io/drivers/doorbird](https://directorlink.io/drivers/doorbird).

### Known issues

- **The gate (relays) and live video are not yet confirmed on a real DoorBird** (the reason for the beta).
- **Control4 Intercom and audio/SIP are not included.** Installers who use Control4 Intercom with the DoorBird keep the official DoorBird driver for that; both can run side by side.
- **One HTTP call per event:** if a DoorBird keeps only one HTTP call per event and another app already has it, that event stays with the other app (Status says which). The D2101KV tested keeps several.
- **Relays of a paired I/O Door Controller** can be opened, but the DoorBird does not report when they open by themselves.
- **Away from home** (4Sight), pictures and live video are not expected to work: the camera page holds the home network's address.
