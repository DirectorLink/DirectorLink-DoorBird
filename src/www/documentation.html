DirectorLink · DoorBird BETA

Free, open-source Control4 driver for DoorBird video door stations. Part of DirectorLink Drivers.

https://directorlink.io/drivers/doorbird

Doorbell rings, motion and RFID events, pictures and live video, and the DoorBird's relays for doors and gates. On the home network, with DoorBird's official LAN API.

Free. No subscription, no license key, no account with us. Downloads, updates and help: see the address above.

Setup

  1. Make a DoorBird user for Control4. In the DoorBird app: Settings → Administration (log in with the administration user), User → Add. Turn on the permissions API-Operator, Watch Always, History and Motion, and save. Note its username (for example ghchdi0002) and password.
  2. Give the DoorBird a fixed IP address in the router.
  3. In this driver's properties enter Address (the DoorBird's IP), Username and Password. Status says Online - events live within half a minute.
  4. Doors and gates: under Connections → Control, bind Relay 1 (and the others) to a Control4 Relay Door, Gate or Garage Controller.

Next to the official DoorBird driver. Both can run on the same DoorBird and the same controller, each with its own DoorBird user. This driver changes only what it made on the DoorBird. Control4 Intercom and audio/SIP are not part of this driver: if you use Control4 Intercom with the DoorBird, keep the official DoorBird driver for that.

How it works

Events, the way Home Assistant does it: the driver runs a small HTTP server on the controller and adds its own HTTP calls on the DoorBird, named DirectorLink (doorbell 1), DirectorLink (motion), DirectorLink (RFID), DirectorLink (relay 1), each with a random token in its address. It puts them into the DoorBird's schedule for each doorbell button, motion, the RFID tags and each relay, the whole week. Every other HTTP call, push notification, SIP call and relay in the schedule stays as it was: each entry is read just before it is written and checked right after, and put back if the DoorBird dropped or changed anything else. The event server listens on a port from 47300, shown in Events. The driver takes a call only from the DoorBird's address and with its token. The same event again within 5 seconds is one event.

Pictures and video: the camera's Properties page gets the DoorBird's address and this user's Basic login: bha-api/image.cgi for pictures, RTSP H.264 (mpeg/media.amp, port 554 or RTSP over HTTP on 8557) for live video, MJPEG (bha-api/video.cgi) as the fallback. Change the login in the driver's properties, not on the camera page: the driver puts the page back.

Relays are pulsed (open-door.cgi): the DoorBird energizes the relay for its own set time. A relay is never held. A second pulse for the same relay within 2 seconds is not sent.

Leaving the DoorBird: when the Address changes, or you run Remove From DoorBird, it takes its HTTP calls out of the schedule first and deletes them after. Run Remove From DoorBird before deleting the driver: a deleted driver starts the same, but Control4 may stop it before it is done.

Programming reference

Events

Ring (any button) · Doorbell Pressed (Button 1), one per button · Motion Detected · Alert (motion, with Alert On Motion) · RFID Read · Door Opened (Relay 1), one per relay · Door Opened (any relay) · DoorBird Online · DoorBird Offline.

Variables

DIRECTORLINK_CAMERA, DIRECTORLINK_CAMERA_KIND, LAST_ALERT, LAST_RING, LAST_MOTION, LAST_DOORBELL (the button), LAST_RFID, LAST_RELAY, LAST_DOOR_OPENED, LAST_EVENT (STRING); ONLINE (BOOL). Times are ISO 8601 UTC, for example 2026-10-05T18:30:00Z.

Commands, conditionals, connections

Commands: OPEN_DOOR (a relay of the DoorBird), LIGHT_ON (the IR light), SET_ALERT_ON_MOTION (On, Off, Toggle). Conditionals: DoorBird is Online · Alert on motion is On. Connections: Relay 1, Relay 2, ... one per DoorBird relay (RELAY, a pulse only). Notification attachment: Picture at the last ring or motion alert.
